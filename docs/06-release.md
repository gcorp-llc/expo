# راهنمای نسخه‌گذاری، به‌روزرسانی OTA و انتشار (Release & OTA Guide)

---

## ۱. قواعد شماره‌گذاری نسخه (Versioning)

در فایل `app.config.ts`:
- **version:** نسخه عمومی قابل مشاهده توسط کاربر (مانند `1.0.0`).
- **android.versionCode:** عدد صحیح مثبت افزایشی برای اندروید (مثال: `100`). هر بار انتشار به گوگل پلی استور نیاز به افزایش این عدد دارد.
- **ios.buildNumber:** رشته یا عدد افزایشی برای اپ استور (مثال: `"1"` یا `"1.0.0"`).

با تنظیم `"autoIncrement": true` در `eas.json`، سرویس EAS Build در هر بیلد به طور خودکار این مقادیر را افزایش می‌دهد.

---

## ۲. به‌روزرسانی آنلاین بدون نیاز به استور (Over-The-Air Update با EAS Update)

برای انتشار رفع باگ‌ها، اصلاح استایل‌ها، و تغییرات جاوااسکریپتی بدون نیاز به ارسال فایل به گوگل پلی یا اپ استور:

### انتشار آپدیت روی کانال پیش‌نمایش (Preview):
```bash
eas update --channel preview --message "رفع باگ رابط کاربری سبد خرید"
```

### انتشار آپدیت روی کانال عمومی (Production):
```bash
eas update --channel production --message "به‌روزرسانی محصولات و ترجمه‌ها"
```

---

## ۳. بازگردانی اضطراری تغییرات (Rollback)

در صورتی که آپدیت OTA خطایی در سیستم کاربران ایجاد کرد:
```bash
# بازگردانی به آپدیت قبلی
eas update:rollback --channel production
```

---

## ۴. چک‌لیست قبل از انتشار نهایی (Pre-Release Checklist)

- [ ] اجرای `pnpm run type-check` و عدم وجود هرگونه خطای تایپ.
- [ ] اجرای `pnpm run lint` و رفع هشدارهای فرمت کد.
- [ ] اجرای `pnpm run test` و قبولی ۱۰۰٪ تست‌های واحد.
- [ ] اجرای `pnpm run doctor` و تایید هماهنگی با SDK 58.
- [ ] بررسی عدم وجود مقادیر محرمانه یا توکن‌های تست در کدهای برنامه.
- [ ] بررسی عملکرد زبان‌های راست‌به‌چپ (فارسی RTL) و چپ‌به‌راست (انگلیسی).
- [ ] تست کامل بازگشت تراکنش موفق و ناموفق در پرداخت تستی استرایپ.
